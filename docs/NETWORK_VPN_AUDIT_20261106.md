- Ошибки 500 в \`domain/push\` встречались 08:32–09:09 UTC. Все 23 соответствовали PostgreSQL SQLSTATE \`42501\`, тексту \`permission denied for table users\`, контексту проверки \`auth.users\` внутри \`public.promysel_commit_sync_domain\`. Параметры или личные данные запросов не извлекались.

Сравнение с последними серверными снимками не выявило расхождений \`well_id/pad_id/well_number\`. Это не заменяет сравнения с исходным вводом пользователя.
- 225 событий \`app_state\` содержат около 50.5 МиБ текстового JSON (среднее около 230 КиБ), против ~42 КиБ всех 31 замеров. Оценка физического объёма снимков не равна счётчику исходящего трафика Supabase. Не очищать историю автоматически.

## Гипотеза VPN: ещё не доказана

Журналы Edge Functions содержат успешные запросы с географической отметкой RU. Однако геолокация не указывает, включён ли VPN, и не доказывает доступность сервера на конкретном месторождении/операторе.

**Что нужно проверить с проблемного устройства на той же сети:**

1. Открыть \`https://promysel-app.tuqo.ru/diagnostics.html\` без VPN, вручную указать тип сети/VPN и скопировать обезличенный результат.
2. На той же мобильной сети повторить тест с VPN, не меняя другие условия.
3. Сравнить независимую доступность HTML сайта, Flutter JS, SQLite WASM, Supabase Edge, Auth, REST и Storage. Переключение VPN во время сохранения замера не проверять на реальных производственных данных.
4. Если статический сайт доступен, а Supabase не отвечает, изучить DNS, TCP/TLS, маршрут и ограничения провайдера. Браузер не может сам надёжно определить, есть ли VPN.
5. Если Supabase отвечает HTTP 401/403/409/500, это **не** означает сетевую блокировку: смотреть авторизацию, ревизии, роль и серверные логи.
6. Проверку авторизованного обмена, загрузки структуры, офлайн-очереди и корректности истории выполнять на тестовых данных отдельно: публичный диагностический endpoint не подтверждает эти функции.

Новая страница \`tools/promysel_network_diagnostics_v225.html\` добавлена в общую Web/PWA-сборку PR #18 и проверена Node syntax/privacy тестом. Она не использует пароли, токены, геолокацию, IP, браузерное хранилище или POST-запросы. Рабочий TUQO должен отдельно получить обновлённые статические файлы: одно только изменение GitHub не гарантирует обновление домена.

## Сетевое решение после измерений

Если на реальных российских сетях подтвердится стабильная недоступность прямого Supabase, обоснован вариант **собственного TLS API-шлюза** на инфраструктуре, доступной пользователям, с жёстким списком маршрутов (Edge API, Auth, Storage, Realtime по необходимости), проверкой JWT/скоупов, ограничением тела и частоты запросов, защитой от открытого проксирования, журналированием только безопасной метаинформации. Точка размещения должна сама устойчиво достигать Supabase без VPN. Перед использованием провести проверку корпоративной ИБ и требований к размещению данных. Не менять API endpoint без испытаний и плана отката.

Если прямой API доступен, а ошибки только 409/500, сначала исправлять конфликты ревизий, права, синхронизацию и офлайн-очереди; прокси их не исправит.

## Границы проверки

- Не проводились испытания через реальные SIM-карты российских операторов, с/без VPN на одном устройстве и многопользовательские офлайн-сценарии. Результат «VPN влияет» пока **не подтверждён**.
- Не вводились новые пользователи, не отправлялись замеры, не удалялись записи и не менялись RLS/SQL permissions.
- TUQO не обновляется самим коммитом: нужно проверить опубликованный \`promysel-release.json\` после отдельной публикации.
- Цель 5 ГБ egress в расчётный период пока не подтверждена по статистике платёжного периода; размер \`app_state\` — основание для дальнейшей оптимизации без потери истории.
