# Промысел: стабильная и разработческая версии

Создано разделение фронтенда:

- **Сотрудники:** https://promysel-web.pages.dev — рабочая версия. Публикация только после явного ручного действия и проверки. Никакие push-коммиты main не обновляют этот URL.
- **Разработчик:** https://dev.promysel-web.pages.dev — превью-версия. Каждый успешный push в main обновляет только ветку `dev` существующего Cloudflare Pages. Видна метка «РАЗРАБОТКА».
- **Исходники:** GitHub main — разработка; ветка stable — последний опубликованный релиз (изначально commit ec2717ca). Автоматический Web workflow НЕ обновляет stable.

## Выпуск готовой версии сотрудникам

1. GitHub Actions → Build Promysel Web for iPhone → найдите успешный прогон на main, где прошли анализ и тесты.
2. GitHub Actions → «Promysel — вручную опубликовать проверенную Web-версию» → Run workflow.
3. Введите ID успешного прогона и подтверждение `PROMOTE`.
4. Публикация на stable URL разрешена только после подтверждения; CI автоматически проверяет успешность и исходную ветку. Архив сборки хранится 3 дня.
5. После проверки выпуска GitHub ветка stable перемещается на выпущенный commit.

## ВНИМАНИЕ: изоляция данных — отдельный этап

Обе Web-ссылки ПОКА используют **один production Supabase** (Auth, БД, Storage, Edge Functions). Изменения SQL, серверных функций, регистрации, тестовые сообщения и редактирование в разработческом интерфейсе могут воздействовать на сотрудников. Поэтому ДО создания отдельного Supabase staging:

- Разработческую ссылку использовать только для просмотра изменений UI без реальных мутаций данных.
- Не выполнять разрушающие тесты, регистрацию тестовых сотрудников, правки скважин и создание/удаление чатов в dev-интерфейсе.
- Для настоящей независимости создать Supabase development branch / отдельный проект (может потребоваться платный тариф). Ветка имеет свою БД, API, Storage, Auth и Edge Functions и не наследует пользовательские записи.
- Подменить API endpoint/public key в dev-сборке (не только сам адрес сайта) и настроить авторизацию, подписки, загруженные файлы, регистрацию и E2E-тесты.
- Серверную Edge Function и миграции сначала изменять на staging, затем после утверждения отдельно публиковать в production.

## Доступ без VPN

Обе страницы Cloudflare Pages, так что проблема отдельных провайдеров с Cloudflare сохраняется. Для рабочих сотрудников нужен независимый VPS/домен, описанный в `deploy/vpnfree/README.txt`. На VPS также нужны два разных каталога/домена, например `app.example.ru` для stable и `dev.example.ru` для разработки.

Если известен независимый VPS, можно развернуть обе версии там после проверки HTTPS и Supabase-прокси.
