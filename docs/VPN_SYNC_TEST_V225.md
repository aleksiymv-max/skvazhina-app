# v2.25: сравнение связи с Supabase с VPN и без VPN

Действующий раздел: **Меню → О приложении → Состояние сервера и синхронизации**.

## Как проверить на одном телефоне

1. Откройте актуальную v2.25 и войдите под своим аккаунтом, выберите месторождение.
2. Оставайтесь на одной сети (например, мобильный интернет). В системных настройках телефона **выключите VPN**, вернитесь в приложение.
3. В поле «VPN» выберите **«Выключен»** и нажмите **«Проверить только API (без отправки)»**.
4. Включите VPN, не меняя Wi-Fi/мобильного оператора, вернитесь на тот же экран.
5. Укажите **«Включён»** и повторите проверку. Нажмите «Скопировать сравнение» и отправьте результаты разработчику. Если браузер перезагрузит страницу при смене сети, скопируйте первый результат отдельно.
6. Не очищайте кэш или данные приложения при неотправленных обходах.

## Что проверяется

- **GET** к фактическому API \`https://xptmcufhuvtcunqzlsme.supabase.co/functions/v1/promysel-compat/v1/sync/domain/revisions\` через тот же сетевой путь и JWT, которые используются обычной синхронизацией. Тело ответа должно содержать \`revisions\`.
- Измеряется длительность ответа (\`Stopwatch\` в миллисекундах) и выводится код результата: \`HTTP_200\`, \`HTTP_401\`, \`HTTP_403\`, \`HTTP_5xx\`, \`SYNC_API_TIMEOUT\`, \`SYNC_API_NETWORK\` и др.
- Тайм-аут проверки: 12 секунд.
- Отдельный тест **не создаёт замеры, не выполняет POST и не изменяет курсор синхронизации**. Результат \`HTTP_200\` подтверждает доступ к защищённому API и БД, **но не** подтверждает выгрузку локальной очереди или полную доставку обходов.
- VPN определяется только по явному выбору пользователя: браузер не может надёжно обнаруживать или управлять VPN.
- Копируемый отчёт содержит лишь время, статус, код и задержку. Не включаются учётные данные, идентификаторы персонала, записи скважин, значения параметров или секреты.

## Как интерпретировать

| Результат | Значение |
| --- | --- |
| Без VPN: \`SYNC_API_TIMEOUT\` / \`SYNC_API_NETWORK\`; с VPN: \`HTTP_200\` | Сильное свидетельство сетевой зависимости на этой конкретной сети, дополнительно проверить DNS/TLS/маршрут |
| Оба раза \`HTTP_200\` | API доступен в обоих случаях, искать проблемы в сохранении, курсоре и локальной синхронизации |
| \`HTTP_401\` | Сервер отвечает, но токен отклонён/истёк; сетевой блокировки этим не доказать |
| \`HTTP_403\` | Сервер отвечает, но роль или доступ к месторождению не разрешены |
| \`HTTP_409\` | API доступен, произошло противоречие версий/ревизий (для текущего read-only маршрута не ожидается) |
| \`HTTP_500\` | Сервер доступен, требуется поиск ошибки в логах Edge Functions/PostgreSQL |
| \`NO_SESSION\` | Требуется вход и выбор месторождения; сетевой тест не выполнялся |

На текущей инфраструктуре TUQO раздаёт статическое Flutter-приложение; Supabase запрашивается **напрямую**, поэтому удачная загрузка главного экрана сама по себе не доказывает доступность API без VPN.

## Сборка и публикация

После зелёного Web CI необходимо подтвердить доступность v2.25 в тестовом окружении. Для TUQO подготовка ветки \`tuqo-production\` — отдельный этап: наличие коммита не гарантирует публикации на \`promysel-app.tuqo.ru\`. Сверять \`promysel-release.json\`, а не ориентироваться только на GitHub Actions.
