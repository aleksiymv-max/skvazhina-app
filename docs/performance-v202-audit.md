# Промысел v2.02 — аудит производительности и логики фоновой работы

Дата: 05.11.2026. Область: Flutter Web/PWA и общий исходный код для Android; Supabase `promysel-compat`.

## Выявленные причины нагрузки

1. Фоновые задачи разных экранов продолжали опрашивать сервер, если экран сохранялся в `StatefulShellRoute.indexedStack`.
2. Список чатов, присутствие сотрудников и полевая синхронизация могли инициировать независимые запросы, даже когда Web-приложение свёрнуто.
3. Любое изменение позиции единственного активного видео/аудиопроигрывателя оповещало *все* видимые пузырьки голосовых и видеосообщений — лишние сборки при скролле.
4. Переключение вкладок сохраняло проигрыватель в уже скрытой ветке, и декодирование могло продолжаться за кадром.
5. Список сотрудников переопрашивался при частых навигациях, хотя существует общий кэш.
6. `sync/pull` делал выборки истории даже при отсутствии более новых событий.

## Принятые правила приоритета

| Категория | Новый порядок работы | Сохранность |
|---|---|---|
| Ручные действия, сообщения, сохранение замеров | Немедленно, независимо от фоновой видимости | Существующая офлайн-очередь и idempotency не изменены |
| Фоновая синхронизация месторождения | Один таймер 150 с, только видимое приложение; продолжение после возобновления через существующий lifecycle | Модификации и ручная синхронизация не ограничиваются |
| Чаты: счётчик непрочитанных | Один опрос не чаще 30 с, только видимое приложение; обновление при возвращении | Не удаляет данные при сетевом сбое |
| Открытый чат | Опрос новых сообщений только в активной переписке; видео/аудио при смене вкладки приостанавливаются | Очередь отправки сообщений сохраняется |
| Персонал | Общий кэш 2 мин; `force:true` после изменения прав и при ручном обновлении | Согласование не зависит от TTL |
| Присутствие сотрудников | Используется существующий единый TTL, опрос таймерами только для видимого экрана | Ручная отметка сотрудника не ограничивается |
| Видеозаписи и голосовые | Текущий проигрыватель обновляет только относящийся к нему пузырёк и верхнюю панель | Вложения/ссылки сохраняются |
| Навигация | Встроенная ветка Flutter остаётся смонтированной для быстрого возврата, но скрытые ветки не декодируют видео и не делают лишний polling | Выбранные разделы и пользовательское состояние сохраняются |
| Push | Ограничено вызовами из скрытого приложения; существующий контроль идемпотентности сохранён | Подписки не меняются |
| Supabase `sync/pull` | Для неизменённого курсора выполняется индексная проверка и возвращается пустой список; при изменениях/восстановлении старый алгоритм | История и восстановление не сокращены |

## Факты до доработки

Логи Supabase за доступный период: 770 успешных чтений `sync_events`, 1219 обращений к Auth User, 1214 чтений `field_memberships`, 1003 чтения `oil_fields`. Это суммарные серверные операции, а не количество уникальных пользовательских действий.

Таблица `sync_events`: 186 событий и приблизительно 28,2 МБ полезной нагрузки. Имеется индекс `sync_events_pull_idx(field_id, sequence)`. `EXPLAIN ANALYZE` для пустой проверки курсора использовал этот индекс (без чтения самих JSON-полезных нагрузок). Репозиторий с историческими событиями не очищался.

## Контроль сборки

- Flutter `analyze`, комплект штатных unit/widget тестов и дополнительные тесты скрытого/активного приложения.
- Проверки исходников: корректные подписки/отписки слушателей, отдельные перерисовки медиа, сохранность локальной очереди.
- Web-архив для TUQO, тестовая публикация на ветке dev Cloudflare.
- Сервер: Supabase `promysel-compat` v24, опубликован отдельно.

## Что нельзя утверждать без реального устройства

Фактические FPS, 90-й и 99-й перцентили времени кадра, нагрузку CPU и RAM на телефонах, поведение на мобильных операторах и задержку отправки при разных скоростях сети. Для этого требуется тестирование release-сборки на устройстве и сбор метрик Flutter DevTools.

Увеличение кэша не заменяет актуальную проверку при ручном согласовании сотрудников; для таких действий сохранена принудительная загрузка. Ручные действия и фоновые задачи имеют разный приоритет.

Новые механизмы не удаляют пользователей, месторождения, кусты, скважины, обходы, историю или сообщения.
