# «Промысел»: собственный сервер сборок на ноутбуке

Статус: **черновик в отдельной ветке**, не внедрён в `main`. Рабочий сайт и текущие workflows не меняются.

## Что подготовлено

- `.github/workflows/promysel-local-web.yml`: запуск **вручную**, публикация только DEV в Cloudflare Pages.
- `.github/workflows/promysel-local-android.yml`: запуск **вручную**, сборка Android ARM64 из ранее архивированного рецепта.
- Оба задания используют `runs-on: [self-hosted, Linux, X64, promysel-local]` и допускают сборку только из `main`.
- Нет `push`, `pull_request`, `schedule`; по умолчанию ничего не запускается.
- Продукционная публикация остаётся в отдельном, ранее существовавшем workflow с подтверждением.

## Техническое ограничение

**Выключенный ноутбук не может выполнять сборки.** Runner будет `Offline`; задача ждёт подключения (максимум 24 часа, затем завершается). GitHub не включает ноутбук.

Возможные режимы:
1. Ноутбук включён, в сети, от электропитания; экран выключен, крышка закрыта, сон отключён при закрытии. Можно запускать сборку с телефона.
2. Ноутбук спит и поддерживает Wake-on-LAN, а роутер / другое доверенное устройство в сети отправляет пакет пробуждения. Это надо проверить на конкретной модели. Пробуждение из полного выключения через Wi-Fi, как правило, недоступно или ненадёжно.
3. Включать ноутбук вручную перед сборкой. Такой вариант не потребует настройки WOL.

## Подготовка ноутбука, когда к нему появится доступ

1. Выяснить ОС, RAM, объём свободного SSD и тип подключения к роутеру.
2. **Для этого проекта нужен Linux x64 runner.** Нативный Windows runner не подходит для существующих Bash/`apt` шагов. На ноутбуке с Windows можно установить Ubuntu отдельно либо попробовать Ubuntu в WSL2 (но необходимо отдельно обеспечить запуск WSL2 и runner после включения, а WOL проверить на Windows). При невозможности установить Linux — адаптировать каждый шаг workflow под Windows до запуска.
3. Установить Git, Python 3, unzip, curl, Java/JDK, Android SDK с нужными платформами, Node.js/npm, Flutter и нужные зависимости системных библиотек. Проверить `flutter doctor -v`, `java -version`, `node -v`, `python3 --version`. Убедиться, что хватает диска для Android SDK и кэшей Gradle/Flutter.
4. В репозитории открыть **Settings → Actions → Runners → New self-hosted runner**, выбрать Linux x64 и выполнить команды GitHub **на ноутбуке**. При регистрации указать дополнительную метку `promysel-local`. Регистрационный токен не пересылать в чаты.
5. Настроить runner как системную службу (для Linux через созданный скрипт `svc.sh`) и отдельного непривилегированного пользователя. Проверить статус `Idle` в GitHub.
6. Не добавлять в ноутбук production-секреты, если они не нужны. Секреты Cloudflare остаются GitHub Actions Secrets; доступ к Docker сокетам и правам администратора runner не давать без необходимости. Хранить ноутбук с шифрованием диска и обновлениями.
7. Проверить безопасность: только ручные workflows с `main`, никакого выполнения произвольных PR с чужим кодом; runner выделен только под приватный проект. Не запускать PR-based тесты на постоянном self-hosted runner.
8. После реальной проверки локальной сборки и настройки ноутбука — предложить изменения отдельным PR для переноса в `main`. Не изменять стабильную production-версию без подтверждения.
9. Проверить первую Web-сборку, APK-сборку и сравнить результирующие артефакты с рабочими. Проверить, что GitHub-hosted минуты не расходуются.

## Wake-on-LAN / включение по запросу

Потребуется поддержка BIOS/UEFI + сетевой карты, разрешение wake в ОС и способ доставки WOL-пакета в домашнюю сеть (роутер с WOL или другое надёжное постоянно включённое устройство). Подключение через Ethernet предпочтительнее. У многих ноутбуков WOL из полного выключения не работает. Не пробрасывать небезопасные порты роутера в интернет; предпочтительнее VPN/встроенный защищённый механизм роутера.

Схема «ноутбук выключен, других работающих устройств нет, сборки по команде из GitHub всё равно автоматически начинаются» **не гарантируется и обычно не работает**.

## Стоимость и ограничения

Собственные runner-задания не расходуют стандартную месячную квоту hosted-минут GitHub. Электроэнергия, оборудование, интернет и ресурсы хранения артефактов остаются расходами/лимитами. GitHub ограничивает максимальное время ожидания offline runner 24 часами и время отдельных заданий.

Документация: https://docs.github.com/en/actions/reference/runners/self-hosted-runners

**Эта ветка — подготовка, а не подтверждение работающей локальной сборки.**
