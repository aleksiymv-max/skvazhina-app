# v1.93: полное удаление учётной записи сотрудника

Причина: прежняя кнопка начальника блокировала членство, кнопка администратора удаляла только field_memberships. Auth-пользователь и approved registration_request оставались, поэтому email не освобождался.

Исправление: после явного подтверждения выполняется серверная проверка роли и месторождения, отказ при доступах к другим месторождениям и попытке удалить системного администратора, затем Supabase Auth hard-delete. Удаление каскадно чистит членство, авторство в операционных записях обезличивается (NULL), история скважин/замеров/общих чатов и журнал событий не уничтожаются. Пуш-подписки и регистрационные заявки чистятся серверным процессом. Администратор получает восстановление для ранее удалённых пользователей, оставшихся без привязки к месторождению.

Миграция `supabase/migrations/20261105_personnel_account_erasure.sql`: 17 FK, ON DELETE SET NULL/CASCADE, не меняет данные до явного удаления аккаунта. Для Storage-объектов со связанным владельцем Auth может отклонить удаление: API должен сообщить об ошибке, а не заявлять об успехе. При расхождении авторизации старые JWT могут быть действительны до истечения срока; ограничения прав на уровне членства остаются в силе.

Сохранение производственной истории юридически и функционально отличается от удаления персональных данных профиля; в чатах и журналах оставшийся текст сообщения не очищается автоматически. Не следует обещать полное стирание всех упоминаний ФИО из произвольных документов.

Это изменение затрагивает ОБЩУЮ Supabase-систему для DEV и PROD, требует серверной миграции и развёртывания Edge Function; Flutter Web и Android строятся из общего исходного кода, APK не требуется.
