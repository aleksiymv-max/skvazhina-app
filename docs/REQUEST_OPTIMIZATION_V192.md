# v1.92 — аудит маршрутов и запросов

Проверены маршруты Supabase по журналам, клиентские источники запросов и согласованность Web/Android. **Серверная база и Edge Functions не изменены.**

## Наблюдения
- `/v1/sync/pull`: за окно логов 63 HTTP 500, но большинство в ранние часы 4 ноября UTC. Последующие успешные запросы не доказывают окончательного устранения причины. В таблице `sync_events` 133 записи `app_state` с суммарным payload около 23 МБ; полные снимки могут быть дорогими при чтении.
- `/promysel-chat/rooms`: отдельные запросы до 41 с; `/messages` — до 43 с. Клиентский оптимизатор не устраняет медленный серверный запрос.
- Присутствие, персонал, согласования и уведомления могли вызываться из нескольких экранов.

## Исправления клиента
- Заявки согласования запрашиваются только администраторами и начальниками цеха; запросы совмещаются, повторное чтение ограничено TTL 20 с; смена пользователя/месторождения очищает кеш и **обязательно запускает запрос для нового владельца**.
- Месторождения загружаются при открытии регистрации, а не обычной формы входа. Запросы совмещаются и кешируются на 2 минуты, после изменения месторождения принудительно обновляются.
- Присутствие сотрудников повторно использует кеш между экранами.
- Слушатели синхронизации привязываются один раз и удаляются при dispose; фоновый интервал увеличен с 90 до 150 секунд.
- Отправка push-уведомлений не вызывается при каждом изменении синхронизируемого снимка; добавлено ограничение частоты в 3 минуты для пары пользователь/месторождение.
- API чатов остаётся отделённым от производственной синхронизации; API заданий/обходов/графиков не заменялись сторонними маршрутами.

## Границы проверки
Статические проверки проверяют конкретные контракты маршрутизации, но не гарантируют полную корректность синхронизации при одновременных изменениях. Нужны реальные E2E-тесты нескольких устройств и серверный анализ тяжёлых снимков. Изменения распространяются на общий Flutter-код Web/Android, APK не собирается. PROD публикуется только после успешной сборки и проверки DEV.
