# После успешного /probe: проверка защищённого чтения

Наблюдение 6 ноября 2026 года: на iPhone открыт JSON
`{"status":"ok","service":"promysel-compat","backend":"supabase"}`
с `https://d5dcuqhl81fmr7cmipov.4kscn31j.apigw.yandexcloud.net/probe`.
Проверен маршрут для публичного GET. Скриншот показывает **значок Wi-Fi**, поэтому мобильный LTE без VPN ещё не проверен.

## Следующий тест в первую очередь

На **том же телефоне** выключить Wi-Fi **и** VPN, открыть
`https://d5dcuqhl81fmr7cmipov.4kscn31j.apigw.yandexcloud.net/probe`
через Safari. Нужны HTTP 200 и JSON `status=ok`. Проверить также
с VPN выключенным на другом операторе, если сотрудники пользуются разными SIM.

## Вторая фаза (готова конфигурация, ещё НЕ установлена в Yandex Cloud)

`promysel-auth-readonly-stage.openapi.yaml` — только два маршрута:

1. `GET /probe` — публичное чтение здоровья сервиса;
2. `GET /v1/sync/domain/revisions?fieldId=<поле>` —
   безопасное защищённое чтение. Явно пробрасывается только
   `Authorization` существующего JWT пользователя и `fieldId`.
   Сервер Supabase проверяет токен, действующую сессию и
   принадлежность указанному месторождению; без токена 401, без прав 403.
   Никаких POST, административных операций или service_role.

CORS настроен **только** для тестового происхождения
`https://dev.promysel-web.pages.dev`; рабочая версия TUQO пока
не должна использовать этот маршрут.

### Контрольные критерии

- Без токена и с тестовым `fieldId` сервер отвечает 401, не 200.
- Действительный пользователь под реальной авторизацией читает ревизии
  своего месторождения: 200 и `revisions`, без чужих данных.
- Попытка чтения постороннего месторождения: 403.
- И с VPN, и без VPN защищённый GET проходит на целевой мобильной сети.
- Ни один вызов не меняет БД, курсоры, очереди или файлы.

**Не пересылать JWT, пароль, refresh_token, service_role или другие
ключи в ChatGPT / screenshots / чужие формы.**

## Почему пока не переключать приложение

Приложение использует также `/auth/v1`, `/storage/v1`,
`/functions/v1/promysel-compat`, REST и вложения.
Yandex API Gateway имеет лимит **2,5 МБ** на размер запроса и ответа,
поэтому нельзя вслепую проксировать все фотографии, видео,
документы и полные снимки. Требуется отдельное тестирование и
специальное решение для больших файлов/подписанных URL.

Рекомендована поэтапная интеграция: мобильный маршрут → JWT GET →
полные sync pull/push → auth/login/refresh → вложения → realtime;
затем ограниченный canary → рабочая версия. До переключения
согласовать новую точку обработки производственных данных с ИБ.
