# Промысел: первый тест без VPN через Yandex API Gateway

**Статус:** подготовлена спецификация только для чтения. Шлюз **ещё не создан** в аккаунте Yandex Cloud. Продакшен `promysel-app.tuqo.ru`, Supabase, учётные записи и производственные данные не изменялись.

## Цель

Не переходить сразу на платный VPS и не рисковать данными. Проверить маршруты:
1. телефон сотрудника без VPN → Yandex API Gateway;
2. Yandex API Gateway → реальная Supabase Edge Function `/health`.

Этот тест не включает авторизацию сотрудников, синхронизацию, запись параметров, фотографии или чаты. Он не гарантирует работоспособность всей системы.

## Создание (вручную в собственном аккаунте)

1. Войти в https://console.yandex.cloud/ и выбрать облако/каталог. Для API Gateway требуется активный платёжный аккаунт; проверить настройки бюджета и расходы заранее.
2. Открыть **API Gateway → Создать API-шлюз**.
3. Имя: `promysel-supabase-test`. В поле **Спецификация** вставить **точный текст** файла `deploy/yandex-gateway/promysel-health-probe.openapi.yaml` (без добавления секретов).
4. Создать шлюз. Не создавать ВМ, базу данных, ключи service_role, облачные функции или публичный доступ к частным методам.
5. Открыть полученный в карточке шлюза **Служебный домен**. Затем открыть URL `https://<служебный-домен>/probe` с VPN и без VPN на **одной и той же мобильной сети**. Проверять не только статус 200, но и содержание JSON (должен отвечать исходный `/health`).
6. Прислать **только** служебный домен и HTTP-код/текст ошибки или скриншот ответа. Этот домен не пароль и не секрет.

Важно: если тестовый шлюз выдаёт 502/504 или долгие тайм-ауты, Yandex API Gateway может не иметь маршрута до Supabase. В таком случае не переключать приложение на него.

## Что дальше при успехе

- Тест защищённого GET на **реальную авторизацию**, с сохранением `Authorization`, `apikey` и query-параметров, предварительно настроив разрешённые CORS-источники; без раскрытия JWT в логах и отчётах.
- Отдельно проверить `POST` синхронизации, поведение очередей, `401/403/409`, время ответа, отсутствие дублей и поддержку мобильных сетей.
- В перспективе **необходимо отдельно** поддержать `/auth/v1`, `/rest/v1`, `/storage/v1`, подписанные ссылки на вложения, возможные WebSocket-подключения `/realtime/v1`, редиректы входа и выдачу файлов. Простое проксирование одного `/health` их не заменяет.
- Ограничение на размер запроса или ответа Yandex API Gateway — **2,5 МБ** по официальной документации. Поэтому большие фото, видео, документы и некоторые полные снимки нельзя автоматически перенаправлять через тот же шлюз.
- Проверить обработку персональных/производственных данных: зарубежный Supabase остаётся исходной системой, а Yandex Cloud — дополнительной точкой обработки трафика. Необходимо согласование с владельцем данных и ИБ.
- После проверки маршрутов выпускать только отдельную версию для тестирования; рабочую версию не трогать до полной функциональной проверки.

## Стоимость

По официальной документации Yandex Cloud первые 100 000 обращений к API Gateway за месяц не тарифицируются; сверх лимита платно. Исходящий трафик также тарифицируется с учётом бесплатной квоты. Платёжный аккаунт и контроль бюджета обязательны, бесплатная квота **не означает нулевой счёт без ограничений**.
