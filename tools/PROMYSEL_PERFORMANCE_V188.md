# Промысел 1.88 — производительность и стабилизация чатов

Срез журналов Supabase, 4 ноября 2026 года: 12-часовая выборка содержит GET /rooms (n=174, ~6.9 с в среднем), GET /messages (n=75, ~7.2 с), /v1/sync/pull с ошибкой 500 (n=103). Это исторические данные за 12 часов, включая прежние версии. Свежая 45-минутная выборка после серверной оптимизации была значительно лучше: список чатов n=11, ~508 мс, история n=8, ~641 мс. Не интерпретировать маленькую выборку как доказательство устойчивой скорости на всех устройствах.

Меры в клиентской версии 1.88:
- Анимация записи: отдельный ValueNotifier и обновление только компактной панели, а не списка сообщений четыре раза в секунду.
- Текстовое сообщение: оптимистичный элемент с прежним client_id, подтверждается при получении серверного экземпляра. При ошибке текст остаётся в поле.
- Вложения: декодирование картинок ограничено по размеру виджета, FilePicker не буферизует документы на Android заранее, до двух фото загружаются параллельно с сохранением подтверждённых путей для повторной попытки.
- Публикация медиа: индикатор загрузки без длинных сообщений, подробности только при ошибке с управлением повтором.
- Предпросмотр камеры: кешированный список камер, сама камера остаётся закрыта вне записи.
- Синхронизация: фоновые проверки статусов персонала выполняются с общим TTL ~60 сек, общий опрос SyncService ~90 сек при сохранении немедленной отправки изменённых данных.
- Не меняет схемы хранения сообщений, производственные данные, роли или RLS.
- Критерии фактической приёмки: 2 сотрудника, повторная отправка при обрыве, 30+ сообщений, альбом 2-10 фото, запись 10-60 секунд, возвращение из фона, отсутствие дублей, оценка p50/p95 по логам после пользовательской проверки.
