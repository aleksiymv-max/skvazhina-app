# Промысел 1.86 — стабилизация чатов
Сводка фактической диагностики за 4 ноября 2026 г. (UTC).
В серверных журналах средняя длительность GET /rooms: ~7,9 с (макс. 84,7 с), GET /rooms/{id}/messages: ~8,3 с (макс. 43,5 с); также зафиксированы statement timeout и "database system is not accepting connections". SQL-функция списка чатов сама по себе выполнялась существенно быстрее (миллисекунды); задержки приходились на совокупные сетевые / Auth / DB операции.
Исправления:
- Один авторизованный запрос room-scope вместо трёх последовательных, проверка принадлежности месторождению в SQL.
- GET /rooms авторизуется в той же SQL-функции. RLS включён, публичный EXECUTE не открыт.
- Подписание групповых аватаров одним запросом, проверка отдельных медиа по точному пути вместо листинга до 1000 объектов.
- Клиентский кеш списка/истории только в памяти и раздельно по userId/fieldId; при сбоях уже прочитанное остаётся на экране.
- Отдельные обновления списков и сообщений, увеличены интервалы опроса, убрана двойная загрузка при открытии.
- Одновременные запросы переиспользуют одно обновление refresh-token.
- Вложения на Android передаются потоком, запись с экономными параметрами; на Web по-прежнему используется браузерный буфер.
- Игнорировать тяжёлую загрузку плееров до явного нажатия; сообщение с неудачной отправкой оставлять в форме с повторным использованием uploadedPath и clientId.
Ограничения подтверждения: CI проверяет сборку и статические проверки. Реальный iPhone/PWA, чужие аккаунты, слабый интернет и фоновые уведомления требуют интеграционных испытаний с реальными разрешёнными пользователями.
Рекомендуемые приёмочные критерии: отсутствие потери/дублирования сообщений, видимость кешированной переписки менее 0,5 с (в рамках тёплой сессии), p95 ответа активного сервера < 2 с при нормальной работе БД, фото/голос/видео от 5 до 30 с с ручным retry, офлайн-восстановление и 15-минутная сессия без потери позиции прокрутки.

Дополнительная стабилизация: отключена бесконечная немедленная пересинхронизация при каждом 12-секундном тике; стандартный опрос 60 с, экспоненциальная пауза при серверных ошибках, контроль реконструкции истории раз в 12 часов (доступен ручной recover=1).\n
